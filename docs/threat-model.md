Mandatory flow: `Internet content → UNTRUSTED DATA → bounded extractor/sample → LLM triage → suggested patch → CI → human`. Never `Internet → LLM → production action`.

## 0. Assets, untrusted inputs, trust boundaries

- **Assets:** Bronze captures (irreplaceable, ADR-002); Silver correctness (value, unit, sign, interval); the registries (dataset, metric, host; ADR-022); `main`; the deploy identity; the object-store and Postgres credentials; the backups.
- **Untrusted inputs:** every source payload and every fixture recorded from one; every manifest and golden a target author writes; every pull request, an agent's included; every LLM output.
- **Trust boundaries:** `energy_platform.fetch` (network → platform, ADR-026); the target surface (contributor → platform, ADR-027); code-owner review (PR → `main`); GitHub OIDC plus the namespace `Role` (CI → cluster, ADR-035); Object Lock and the retention rule (cluster → archive, ADR-036); the sandbox (agent → everything, ADR-007).

## 1. Indirect prompt injection

- Mechanism: Only the drift-triage pipeline puts source content in front of an LLM, and it is off the capture/process path (P6-D3, item 12). `extract` builds a bounded sample from the production parser's output (field inventory, at most 3 records, each value at most 64 characters with control characters removed, at most 4 000 characters in total, serialised as JSON); the system prompt is a constant and the sample travels only inside the user message as data. Whatever the model returns is parsed against a strict operation schema (item 11) and ends as a proposal file for a human; nothing the model says is executed.
- Gate: C-58, C-60 · `test` · `tests/triage/test_extractor.py::test_sample_is_bounded_and_data_only`, `tests/triage/test_extractor.py::test_hostile_text_is_truncated_and_stripped`, `tests/triage/test_injection.py::test_hostile_xml_cannot_change_unit_sign_host_or_url`, `tests/triage/test_injection.py::test_hostile_html_cannot_widen_the_patch`, `tests/triage/test_injection.py::test_system_prompt_is_constant`. The malicious backend in `test_injection.py` obeys the injected text (the compromised-model worst case); the gate must hold anyway.
- Residual risk: An injection can still steer the choice among allowed operations (a rename to a wrong but present field); `verify` proves "maps without quarantine", not "maps correctly", so the reviewer and the goldens are the control. Developer-mode agents that read live payloads or web pages while writing a target are exposed with their session's full authority; CI, code-owner review and, where used, the sandbox bound them (item 13). The HTTP LLM backend is not built (D-10), so no real model has been exercised.

## 2. Malicious source response

- Mechanism: A payload is data from end to end. Fetch validates destination, redirects and peer (items 6, 7); Bronze stores the bytes as received, content-addressed; the decoders run with XML entity resolution, network access and huge trees off, openpyxl read-only with `data_only` (no formula evaluation) and a 1 000 000-row cap per sheet; decimals are parsed under the declared separator, never with `float()`. A SOAP `Fault` over HTTP 200, malformed XML, non-decimal text, a period outside the day, one period with two values or a negative value on a `non_negative` metric quarantines the document, and the capture stays in Bronze for replay (ADR-004).
- Gate: C-05 · `lint` · `tests/harness/test_target_surface.py::test_float_call_in_parser_rejected`. No `05` row for decoder hardening; `test` · `tests/parse/test_decode.py::test_external_entities_are_not_resolved`, `tests/parse/test_decode.py::test_soap_fault_over_http_200_is_raised_with_its_reason`, `tests/parse/test_decode.py::test_malformed_xml_is_a_decode_error`, `tests/mapping/test_engine.py::test_non_decimal_text_quarantines`, `tests/mapping/test_engine.py::test_same_period_twice_with_different_values_quarantines`, `tests/mapping/test_engine.py::test_negative_volume_quarantines_the_document`.
- Residual risk: Fetch has a 30 s timeout but no response-size cap, and an XLSX (zip) bomb is bounded only by the pod memory limit (A-8): the run fails loudly, and a body that did fit sits in Bronze under the 90-day lock (a storage cost, not an integrity loss). A plausible but false value from a compromised source is captured faithfully; only the T1/T2 cross-check of shared metrics (`reconciliation_mismatch`, `tests/mapping/test_reconcile.py::test_copy_beyond_tolerance_raises_a_mismatch_in_both_directions`) questions it.

## 3. Dependency hallucination / slopsquatting

- Mechanism: Hash-pinned `uv.lock`, installed with `UV_FROZEN=1` / `--frozen` in CI and in both images; `deps-allowlist.txt` lists every locked package, transitive ones included; a new package needs an ADR and a human (ADR-006: dependency changes are their own gate). `deps-allowlist.txt` and `pyproject.toml` are code-owner paths, and a target PR that touches them is rejected by name. Targets cannot import any third-party package (positive import allowlist, ADR-027 §2), and the sandbox image has no `uv` and no usable `pip`.
- Gate: C-38 · `deps-allowlist`, `lock-check` · `tests/harness/test_deps_allowlist.py::test_unlisted_package_fails`; C-40 · `pr-surface` · `tests/harness/test_pr_surface.py::test_registry_edit_in_target_pr_rejected`; C-12 · `lint` · `tests/harness/test_target_surface.py::test_parser_import_outside_allowlist_rejected`.
- Residual risk: The allowlist checks names, not provenance: a typosquatted name that a human approves passes, so the ADR review is the control. `make ci-bootstrap` installs `uv` by `curl | sh` pinned by version but not by checksum (unlike `make ci-terraform`). Other artefacts are pinned (Actions by commit, C-42; images by digest, C-43; Terraform and the k3s installer by checksum) but every update of a pin is a human judgement.

## 4. Credential exfiltration

- Mechanism: No credential in the repository (`secret-scan` over tracked and staged files); manifests carry only a `secretRef {name, key}` and a credential-looking string in a `fetch` block is refused (ADR-017); fetch redacts secret query parameters in every stored or logged URL and authorization-like headers in logs. The deploy uses no stored secret (GitHub OIDC, item 14); CI runs on `pull_request` with `contents: read`, so a fork PR gets neither secrets nor an ID token. The sandbox holds no secrets and `read_repository` refuses `.git`, `.env`, keys and kubeconfigs; unit tests run with sockets disabled, so a test cannot send anything anywhere (ADR-027 §4).
- Gate: C-26 · `harness-check`, `secret-scan` · `tests/contracts/test_manifest_negative.py::test_credential_looking_string_in_fetch`, `tests/harness/test_secret_scan.py::test_bare_token_is_reported`, `tests/harness/test_secret_scan.py::test_token_next_to_example_comment_is_still_reported`; C-52 · `test` · `tests/harness/test_mcp.py::test_read_repository_confined`; C-36 · `test` · `tests/harness/test_network_block.py::test_socket_constructor_is_blocked`; no row · `test` · `tests/fetch/test_plan.py::test_rest_auth_from_secret_ref_is_sent_but_never_stored`, `tests/fetch/test_client.py::test_secret_query_parameter_is_redacted_in_the_result`, `tests/harness/test_ci_wrappers.py::test_deploy_demo_workflow_uses_oidc_and_nothing_stored`.
- Residual risk: `secret-scan` is a regex over the working tree and does not scan history (item 15). `secretRef` resolves any `<NAME>_<KEY>` in the pod environment, so a target manifest could name the Bronze credentials (`{name: BRONZE, key: secret-access-key}`) as its `auth` value; the value still goes only to a registered host over https and is redacted in logs, but no gate scopes a target's `secretRef` to its own secrets, so the manifest review is the control. An unsandboxed developer-mode agent runs with the developer's files and environment, the credential files outside the repository included (item 13).

## 5. Unsafe shell generation

- Mechanism: ruff TID251 bans `subprocess`, `os.system`, `os.popen`, `importlib`, `ctypes` and `multiprocessing` (with the network modules) everywhere except `energy_platform/fetch/`, `scripts/`, `tests/harness/` and `conftest.py` (ADR-027 §3). Targets cannot import them at all (positive allowlist, ADR-027 §2), and `exec(`, `eval(`, `__import__` and `open(` are refused anywhere in `targets/`. The MCP server has no shell tool, the sandbox image has no `/bin/sh`, and CI workflow steps may only call `make` (ADR-015).
- Gate: C-30 · `lint` · `tests/harness/test_ruff_gates.py::test_http_client_outside_fetch_rejected` (parametrised; includes `import subprocess`, `import importlib`), `tests/harness/test_ci_wrappers.py::test_banned_api_list_covers_every_egress_path`; C-12 · `lint` · `tests/harness/test_target_surface.py::test_parser_import_outside_allowlist_rejected`; ADR-027 §1, no row · `lint` · `tests/harness/test_target_surface.py::test_forbidden_token_in_parser_rejected` (`__import__`, `exec(`, `open(`); C-47 · `test` · `tests/harness/test_mcp.py::test_tool_set_is_exactly_adr_007`; C-37 · `test` · `tests/harness/test_ci_wrappers.py::test_ci_workflow_only_calls_make`.
- Residual risk: Shell is legitimate in `scripts/`, the Makefile and the chart's backup, WAL-ship, restore-drill and replication Jobs (`rclone`, `pg_basebackup`); that is platform code reviewed by the code owner, not gated. A developer-mode agent has a real shell: the bans cover the code it commits, not the commands it runs (item 13).

## 6. SSRF via manifest URL

- Mechanism: ADR-026 layer 2: the host must be in the manifest's `allowed_hosts` **and** in the code-owner host registry (`energy_platform/contracts/hosts.py`; a new host is Route B, ADR-022); https only, 443 unless the registry allows another port, no IP literal; fetch resolves the name itself, rejects private, loopback, link-local/metadata and CGNAT addresses (proxy address included) and re-checks the connected peer. Layer 1: `NetworkPolicy` default-deny egress, capture and backfill pods alone get 443 to public ranges, process, gaps and hook pods get no internet; the demo's k3s enforces it with its embedded controller (ADR-035 §2).
- Gate: C-21, C-22, C-27, C-29 · `harness-check` and runtime · `tests/fetch/test_policy.py::test_host_not_in_manifest_allowlist`, `tests/fetch/test_policy.py::test_host_in_manifest_but_not_in_registry`, `tests/fetch/test_policy.py::test_http_with_manifest_flag_but_registry_forbids`, `tests/fetch/test_policy.py::test_ip_literal_never_a_destination`, `tests/fetch/test_policy.py::test_port_not_in_registry`; C-33, C-35 · `test` · `tests/fetch/test_policy.py::test_private_and_metadata_addresses_rejected`, `tests/fetch/test_policy.py::test_proxy_environment_is_honoured_but_metadata_proxy_is_refused`, `tests/fetch/test_client.py::test_private_resolution_blocks_before_contact`, `tests/fetch/test_client.py::test_peer_mismatch_aborts_even_after_a_200`; layer 1, no row · `test` (with helm) · `tests/harness/test_chart.py::test_only_fetching_roles_get_internet_egress`; live under an enforcing CNI: `make local-egress-test` on kind with Cilium, 2026-09-22, 3/3 (`07` §2).
- Residual risk: Tenant CNI enforcement stays unverified: V-11 is closed as not run (author decision 2026-09-23, `docs/plans/phase-6.md`), so on a tenant cluster layer 1 is declared and the fetch layer is the control known to hold. On the demo the layer-1 probe was not repeated (it ran on kind). Layer 1 is not per-host and its `ipBlock.except` list is static (ADR-026, devil's advocate); `egress.fqdnPolicy: cilium` exists but is off by default.

## 7. Malicious redirects

- Mechanism: ADR-026: the HTTP client never follows redirects; fetch follows up to `max_redirects` (3) itself and validates every hop exactly like the first request (both host lists, scheme, port, resolution, peer). The T2 discovery step, a link extracted by regex from a fetched page and therefore source-controlled, goes through the same policy.
- Gate: C-31, C-32, C-34 · `test` · `tests/fetch/test_client.py::test_redirect_to_unlisted_host_fails`, `tests/fetch/test_client.py::test_redirect_to_private_address_fails`, `tests/fetch/test_client.py::test_more_than_max_redirects_fails`, `tests/fetch/test_client.py::test_redirect_is_followed_by_hand_and_every_hop_checked`; no row · `tests/fetch/test_plan.py::test_discovered_link_on_an_unlisted_host_is_refused`.
- Residual risk: A redirect between two registered hosts is allowed by design (OTE answers with a 302 today, `07` §2), so an open redirect on a registered host can lead only to another registered host. Three hops of a hostile but registered source are still spent before the fetch fails.

## 8. Archive poisoning

- Mechanism: Bronze is content-addressed and written once: a blob's key is its SHA-256, a capture-log entry must match its blob, and every read verifies the content address (ADR-002, ADR-024 §1). Store A carries bucket-level Object Lock COMPLIANCE for 90 days (no overwrite or delete, owner included, V-12); store B is written only by `rclone copy --immutable --checksum` of the whole bucket (a different object at an existing key is an error, nothing is deleted on B) under an OCI retention rule (ADR-036 §1, §3). Postgres archives live under `backups/postgres/<system id>/`, so a re-initialised cluster cannot collide with a locked archive (ADR-036 amendment 1 §6); the restore drill rebuilds from B and compares an order-independent checksum over (observation identity, value) with live. A committed fixture must be a Bronze object whose blob hash matches its entry; archive deletion is Level 3.
- Gate: C-18 · `lint` · `tests/harness/test_target_surface.py::test_fixture_not_a_bronze_object_rejected`; no row · `test` · `tests/bronze/test_bronze.py::test_read_verifies_the_content_address`, `tests/fetch/test_objectstore.py::test_delete_is_refused_without_the_flag_and_works_with_it`, `tests/runtime/test_drill.py::test_a_diverging_value_in_live_is_detected_by_the_checksum`, `tests/runtime/test_drill.py::test_a_replica_missing_a_capture_fails_the_drill`, `tests/harness/test_chart.py::test_dr_workloads_render_behind_their_flags` (`--immutable --checksum`, whole bucket), `tests/harness/test_chart.py::test_wal_archive_is_compressed_shipped_and_pruned` (per-system-id path); `terraform-validate` · `deployment/own-cluster/terraform/roots/hcloud/tests/plan.tftest.hcl` run `demo_sizing_and_controls` (COMPLIANCE 90 d on A; retention rule, versioning off on B).
- Residual risk: The locks stop overwrite and deletion, not insertion: whoever holds the capture credentials can add a well-formed blob and capture-log entry, which `reconcile` will pick up and `replicate` will copy to B; on Hetzner that credential is also the bucket owner (one credential set per project, V-12). A fixture recorded `--from-file` is a well-formed Bronze object, not proof that the source sent those bytes; its provenance is the reviewer's check. After 90 days the owner can delete (Level 3, procedural).

## 9. PR supply-chain attack

- Mechanism: `main` is protected on GitHub (enforced since the repository went public, 2026-09-23): pull request required, the 12 CI jobs as required checks, code-owner review; admins may bypass and every bypass is logged. `CODEOWNERS` (`*` plus the registries, allowlist, Makefile, `.github/`, ADRs) puts the maintainer on every merge; `pr-surface` rejects a target PR that touches anything outside its `targets/<id>/`, names registry and CI paths, and refuses two targets in one PR. Actions are pinned by commit and images by digest; workflows only call `make` and run on `pull_request` with `contents: read`; an MCP bundle is re-verified (paths confined to one target, hashes) before `scripts/apply_pr_bundle.py` writes it, never onto `main`.
- Gate: C-39, C-40, C-41 · `pr-surface` · `tests/harness/test_pr_surface.py::test_target_plus_platform_file_rejected`, `tests/harness/test_pr_surface.py::test_registry_edit_in_target_pr_rejected`, `tests/harness/test_pr_surface.py::test_two_targets_in_one_pr_rejected`, `tests/harness/test_pr_surface.py::test_git_diff_integration`; C-42, C-43 · `harness-check` · `tests/harness/test_workloads.py::test_unpinned_action_rejected`, `tests/harness/test_workloads.py::test_mutable_image_tag_rejected`; C-46 · `test` · `tests/harness/test_ci_wrappers.py::test_codeowners_covers_the_protected_paths`; C-37 · `test` · `tests/harness/test_ci_wrappers.py::test_ci_workflow_only_calls_make`; C-53 · `test` · `tests/harness/test_pr_bundle.py::test_apply_never_touches_main`, `tests/harness/test_pr_bundle.py::test_verify_bundle_rejects_tampering`. Branch protection itself is a GitHub setting, not testable offline.
- Residual risk: CI runs the PR's own code, so a platform PR can edit the gate it is judged by; only code-owner review stops that, and there is one maintainer. The maintainer's own platform commits reach `main` by the logged admin bypass (`docs/plans/phase-6.md`, option (a)), i.e. without a second reviewer. Signed commits are recommended, not required; `ci-bootstrap` fetches `uv` without a checksum (item 3).

## 10. Mapping-level data poisoning (a patch that silently flips a sign or unit)

- Mechanism: Semantics belong to the platform (ADR-005): every `unit` must equal the registry unit, fixed dimension values must match, and each metric's sign rule lives in the registry (`non_negative` quarantines, `non_negative_expected` raises a quality event). A target chooses only source field names, `decimal_separator` (explicit, never detected) and `sign: as_published | inverted`, and may not compute in `parser.py` (no arithmetic, unary minus, timezone conversion or `timedelta`). Goldens assert values on real Bronze fixtures and must name `checked_by`; T1 and T2 cross-check the metrics both publish (`reconciliation_mismatch`); every Silver row carries `sign_convention` and `derivation_id`, so a bad mapping is repaired by `energyctl replay --derivation <bad>` (ADR-023, ADR-016 §4).
- Gate: C-03 · `lint` · `tests/harness/test_target_surface.py::test_normalise_code_in_parser_rejected`; C-16 · `lint` · `tests/harness/test_target_surface.py::test_empty_golden_rejected`; C-17 · `test` · `tests/harness/test_goldens.py::test_wrong_golden_value_fails`, `tests/harness/test_goldens.py::test_missing_expected_row_fails`; C-25 · `harness-check` · `tests/contracts/test_manifest_negative.py::test_unit_mismatch_is_invalid_not_admission`; no row · `test` · `tests/mapping/test_engine.py::test_negative_volume_quarantines_the_document`, `tests/mapping/test_reconcile.py::test_copy_beyond_tolerance_raises_a_mismatch_in_both_directions`.
- Residual risk: `sign: inverted` on a `negative_allowed` metric (every price), a swap of two present source fields or a wrong `interval_label` is structurally valid; if the same PR updates the golden to match, CI is green and the human golden check is the only control (`checked_by` is a claim, not a signature). Reconciliation covers only the metrics both OTE transports publish.

## 11. The triage agent's own output

- Mechanism: The LLM proposes; it never acts (P6-D3). Its answer must parse against a strict JSON schema whose only operations are `rename_source` (metric or time field), `set_decimal_separator` and `add_ignore_field`; every new source name must appear in the extracted inventory and match the name pattern `^[^\W\d][\w .,:()/%@+-]{0,63}$` (an element, attribute or column-header name, never a paragraph); a single refused operation refuses the whole answer; the patched manifest must validate and differ from the original only under `mapping.metrics.*.source`, `mapping.metrics.*.decimal_separator`, `mapping.time.*.source` and `mapping.ignore_fields`, and `verify` re-maps the drifted payload with no quarantine and no missing source. The output is one file, `outbox/triage-<id>-<stamp>.json` (a unified diff of `targets/<id>/manifest.yaml`, the drift report, the model's rationale truncated and labelled untrusted); a human turns it into a Route A PR that meets CI and code-owner review like any other. Units, signs, hosts, URLs, licences, cadence and registries are not expressible as operations and are refused again by the diff check.
- Gate: C-58, C-59, C-60 · `test` · `tests/triage/test_injection.py::test_proposal_touches_only_the_target_manifest`, `tests/triage/test_injection.py::test_invented_source_field_rejected`, `tests/triage/test_injection.py::test_hostile_xml_cannot_change_unit_sign_host_or_url`, `tests/triage/test_injection.py::test_hostile_html_cannot_widen_the_patch`, `tests/triage/test_pipeline.py::test_renamed_field_yields_manifest_only_proposal`, `tests/triage/test_pipeline.py::test_no_drift_no_proposal`.
- Residual risk: Inside the allowed operations a wrong answer can still verify (no quarantine and no missing source is not "the right field"), and `add_ignore_field` can silence a column that carries a new metric; the reviewer and the goldens are the control. The step from proposal to PR is manual today; if it is automated it must go through `open_pr` and `apply_pr_bundle.py` (C-51, C-53), never a push.

## 12. LLM unavailability

- Mechanism: ADR-009 hard requirement: LLM unavailable → the data platform operates normally. Triage is a CLI verb (`energyctl triage`) a person runs over a Bronze capture; no CronJob, hook or capture/process code calls it and the chart renders no triage workload. The default backend is the offline `HeuristicStubBackend`; `UnavailableBackend` (always raises) makes the outage testable: no proposal, a stated reason, nothing else changes. `make local-up`, `make demo` and CI need no LLM credentials (ADR-010).
- Gate: C-61 · `test` · `tests/triage/test_pipeline.py::test_llm_unavailable_returns_no_proposal`; ADR-010 · `demo` (`make demo`, no credentials, offline).
- Residual risk: That no module on the capture/process path imports `energy_platform.triage` is mechanical: the import-linter contract "the capture/process path never imports triage" (`make lint`) and the AST check in the C-61 test. When the HTTP backend is built its outage stays harmless, but its egress must live in `energy_platform/fetch/` with its host in the host registry (P6-D4).

## 13. Agent authority in practice

- Mechanism: ADR-006: Level 3 (merge to `main`, production secrets, `terraform apply`, `kubectl` write, production database mutation, archive deletion) is forbidden to agents. In constrained-agent mode (ADR-007) this is mechanical: the sandbox container has no shell, `git`, `kubectl`, `terraform`, cloud CLI or secret, runs as uid 10001 on the network the operator attaches (default `--internal`, no route), and exposes only the eight MCP tools; writes are confined to one `targets/<id>/`, `record_fixture` goes live only with `--allow-network`, and `open_pr` writes a bundle that someone outside pushes. In developer mode, the mode this repository was built in, MCP is only the preferred route and CI plus code-owner review are the enforcement.
- Gate: C-47…C-53 · `test` · `tests/harness/test_mcp.py::test_tool_set_is_exactly_adr_007`, `tests/harness/test_mcp.py::test_write_outside_surface_refused`, `tests/harness/test_mcp.py::test_write_with_forbidden_content_is_rolled_back`, `tests/harness/test_mcp.py::test_record_fixture_live_needs_server_opt_in`, `tests/harness/test_mcp.py::test_open_pr_refuses_when_gates_are_red`, `tests/harness/test_mcp.py::test_open_pr_writes_a_bundle_and_never_pushes`, `tests/harness/test_mcp.py::test_read_repository_confined`, `tests/harness/test_pr_bundle.py::test_apply_never_touches_main`.
- Residual risk: An agent session that uses the owner's shell and `gh` login is technically the repository admin: it can bypass branch protection (logged), push to `main`, and run `terraform apply` or `kubectl` with the admin kubeconfig. There Level 3 is procedural (CLAUDE.md, the client's permission prompts, the author's explicit instruction); it is mechanical only in the sandbox and for the OIDC deploy identity (item 14), `07` §4.1 records the demo's Level 3 steps run by the agent at the author's request, and `progress.md` (2026-09-23) one mistake made on the way (`kubectl delete node`). No test asserts the sandbox image's contents (no shell, no CLIs); the Dockerfile and `deployment/sandbox/README.md` are the record and Phase 7 is its first real use.

## 14. Deploy identity and the public API port

- Mechanism: The demo deploys with a GitHub Actions ID token, never a stored credential (ADR-015 federation clause, V-14, ADR-035 §2): k3s trusts only `https://token.actions.githubusercontent.com` with audience `energy-platform-demo`, requires `claims.repository == 'jalalhussein1982/energy-platform'` and `claims.ref == 'refs/heads/main'`, maps the token to `gha:<owner>/<repo>`, and binds that user to a namespace `Role` (no ClusterRole); anonymous authentication is off, written explicitly. Port 6443 is open to the internet (ADR-035 §4: GitHub-hosted runner ranges do not fit a firewall); the only credentials it accepts are those short-lived tokens and the admin client certificate, which stays with the author outside the repository. `deploy-demo` is `workflow_dispatch` only; its image job holds `packages: write` only, its deploy job `id-token: write` only.
- Gate: no row · `terraform-validate` · `deployment/own-cluster/terraform/roots/hcloud/tests/plan.tftest.hcl` runs `demo_sizing_and_controls` (issuer, audience, claim rules, anonymous off, API CIDRs), `admin_only_api`, `cloud_init_is_valid_yaml` (authentication file and RBAC survive cloud-init); `test` · `tests/harness/test_ci_wrappers.py::test_deploy_demo_workflow_uses_oidc_and_nothing_stored`. Live, 2026-09-23 (`07` §4.1): anonymous request → 401; the identity reads ReplicaSets, cannot create them, cannot list nodes.

## 15. Public repository exposure

- Mechanism: The repository is public since 2026-09-23: the full history and every Actions log are readable by anyone. The history was checked for credentials before publication (2026-09-23): none found. What the deploy logs print is public by design: the API URL, the cluster CA certificate and the OCI namespace (repository variables, not secrets) and the image digest; the GHCR package stays private and pods pull it with the `ghcr-pull` Secret. ## Residual risks accepted

1. Allowlisted names, not provenance; `uv` bootstrap without a checksum (items 3, 9).
2. No response-size cap in fetch; oversized or zip-bomb payloads are bounded by pod limits only (item 2).
3. `secretRef` is not scoped per target (item 4).

7. A sign inversion, field swap or interval-label change with a matching golden passes CI; the human golden check is the control (item 10).
8. Allowed triage operations can still be wrong; triage stays advisory (items 1, 11).
9. Runtime/triage separation is by construction, not yet an import contract (item 12).
10. Developer-mode agents hold the owner's authority; Level 3 is procedural outside the sandbox (item 13).
11. Public API port; claim rules do not pin the workflow; the deploy `Role` reads namespace secrets (item 14).
12. Public history is permanent and `secret-scan` does not read it (item 15).
