## Decisions taken in this plan

| # | Decision | Why |
|---|---|---|
| P10-D1 | **OTE cadence (10.0).** T1/T2 keep the 15-minute poll (OTE: "continuously after the close of trading for a given 15-minute contract"); their correction re-reads of D-1…D-3 drop from hourly to **once a day** (OTE: "once as a summary for the entire day"). E1 drops from hourly 12:00–23:00 on D-1 to **four reads after publication** (`15 13-16 * * *`, OTE: "once a day, usually after 1:05 p.m."; `06` §1 saw D+1 served at 14:24) with a once-daily correction. Recorded as ADR-033 amendment 3; `01` §5's "(initial)" intervals stay as written, the manifests carry the decided ones. | The source stated its expectation in writing; the admission register exists to respect sources. Freshness for E1 keeps its documented weakness (ADR-037); the day-ahead partition is complete before the day starts either way. |
| P10-D2 | **Ownership in the row, not the view's join (10.1).** `observations.owner_transport` (nullable text) is written by the store at commit from the registry (`DatasetContract.metric(m).owner_transport`), never by the mapping; the view ranks `source_transport = owner_transport` first. `current_rows(transport=X)` becomes *the per-transport current* (best row among X's rows), so the reconciliation copy stays selectable. `_other_transport_rows` compares against each other transport's own current. | The registry is Python; a SQL view cannot read it. A stored column is explicit, indexable, and backfilled once by migration 0004 (a handful of `UPDATE … WHERE dataset_id, metric`). |
| P10-D3 | **Occurrences, append-only (10.2).** `observation_occurrences(observation_id, run_attempt_id, fetched_at, source_published_at)` unique on `(observation_id, fetched_at)`: a version row is inserted once; every capture that produces the same version adds an occurrence; the current view orders by the version's **newest occurrence**. Exact retry of one capture = same `fetched_at` = no new occurrence. Replaying an older capture carries that capture's `fetched_at`, so it never outranks a newer capture (ADR-023 decision 4 kept). `CommitResult.occurrences` counts new occurrences; a process that adds occurrences but no versions is `ok`, not `noop`. The drill's rebuild replays every capture whose payload differs from the *previous* capture of the run (consecutive, not global, dedup) so occurrence order survives a rebuild. | The reviewer's "append-only occurrence representation"; nothing is updated in place. |
| P10-D4 | **Capture generations (10.3).** `mark_recaptured` bumps the fence and clears the lease: an in-flight claim on the older capture loses at commit (`lost_lease`, ADR-024 §4 as written) and the run stays `captured` on the new capture. `reconcile` advances an existing run when the newest Bronze entry is a **later attempt with a different payload** than the run's capture (a re-occurrence of the run's own payload is a poll, not a generation). The reconcile window covers `reconcile_window + correction.days` so a correction to D-3 captured during an outage is found. | Bronze is the truth (ADR-024 §1); the ledger must follow every generation, not the first. |
| P10-D5 | **Replay reclaim (10.4).** `pending_runs(target, now=…)` also returns runs with an unfinished replay attempt whose lease expired; `claim` closes that attempt as `lost_lease` and opens a fresh replay attempt for the new owner. | The dead worker's attempt gets an outcome; the work becomes visible again under the same lease model. |
| P10-D6 | **Create-only capture-log entries (10.5).** `CaptureLog.put_new(entry) -> bool`: memory under a lock, file with `O_EXCL`, S3 with `If-None-Match: *` (412 → `False`) **and** a read-back of the key after the PUT (a store that ignores the header but keeps last-writer-wins shows the other writer's entry). `Bronze.capture` retries with the next attempt number up to 5 times; the blob is content-addressed and shared. The residual (a store that ignores the header *and* races inside the read-back window) is documented in ADR-024 amendment 1. | No database dependency on the capture path; attempt ids are never reused. |
| P10-D7 | **Durable invalidations (10.6, ADR-038).** An invalidation is a Bronze object `invalidations/<target>/<capture_id>.json` (capture id, optional derivation id, reason, recorded by, at) — immutable, replicated to B like everything under the bucket — mirrored into a Postgres table `invalidations` by `reconcile`. Effects: the current view excludes versions produced from an invalidated capture (join through `run_attempts.capture_id`; derivation-scoped when given); `process`/replay of an invalidated capture commits `failed`/`quarantined` with an `invalidated` event and no rows; `reconcile` never points a run at an invalidated entry; the drill skips them and classifies its "extra" versions against them. `energyctl invalidate <target> --capture <id> --reason … --by …` writes the object; recording the nine 22 September captures on the demo is the author's action. | A decision recorded only in a runbook is not a replay input. Raw evidence stays immutable; Silver deletion becomes unnecessary for future cases. |
| P10-D8 | **Target-scoped freshness (10.7).** `count_periods` / `newest_delivery_start` take `target_id` and count the **target's own** current-per-transport rows (`observations → run_attempts → runs.target_id`) with a non-NULL value for **every** metric the manifest maps; a NULL correction withdraws the period. Month-offset targets (`month_start[k]` in the request) get a `month` partition: the month the request names, `expected_periods` from the calendar, `expected_by` = the first cadence instant after that month's end plus `correction.days`. | Seven configured targets are not seven proven streams; version-0 rows cannot complete a version-1 target. |
| P10-D9 | **RPO per failure domain (10.8, ADR-036 amendment 2).** Stated: database-node loss (Silver ≤ 10 min WAL shipment, Bronze 0), store-A loss (= replication interval), whole-environment loss (= replication interval + rebuild). Demo replication interval becomes **15 minutes** (matches the 15-minute capture cadence; `rclone copy --immutable` of a few thousand small objects). Alerts on staleness via kube-state-metrics: `kube_cronjob_status_last_successful_time` for `replicate`, `pg-backup`, `pg-wal-ship` (the same dependency the drill alert already has). `02` gets a dated pointer at its RPO table. | The bound is now true per domain and monitored, instead of implied by a cadence. |
| P10-D10 | **Deployment modes refuse what they do not implement (10.9).** Render `fail`s for `postgres.mode` `cnpg`/`external` with `drills.restore.enabled` (ADR-036 §5 has no backup chain for them yet); the public-443 rule renders only under `egress.fqdnPolicy=none` (Cilium mode carries DNS + FQDN + the object-store rule itself); the policy gate gains a second canary that only the **per-pod** policy denies — the node's own IP (downward API `status.hostIP`) on a closed port: a refused connect (RST) means no policy yet, a timeout means the policy is in force; the metadata canary stays as the fail-closed check. | Honest about the two modes; the FQDN option becomes a restriction; the gate's evidence depends on the pod's policy again after the node-level block. |
| P10-D11 | **Contributor path (10.10).** Triage inventories the decoded document (XML element and attribute names under the record path, JSON keys, sheet header) independently of mapping success, admits the `@attr` convention, carries the pipeline's `unknown_field` events, and reports `drift` when a non-empty document yields zero records. `docs/08` §9 makes plain Git the primary route and the bundle route explicit about `--repo <clean checkout>`. MCP gains `admission_request` (ADR-007 tool table amended: writes `docs/admissions/<id>.md` into the outbox, nothing into the repository). `validate` refuses a `parser.py` until a loader exists (G13 stays deferred, but no longer silently). | The false healthy diagnosis was the worst of the four; the others are the junior's first-hour experience. |
