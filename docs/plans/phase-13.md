## Decisions

| # | Decision | Why |
|---|---|---|
| P13-D1 | **The capture's run identity is the schedule's instant, never the wall clock.** `--scheduled-for` absent and `--live`: the verb takes the CronJob controller's own tick when it is in the pod (`ENERGY_PLATFORM_JOB_NAME` from the downward API; a Job created by a CronJob is named `<cronjob>-<minutes since the epoch>` of its scheduled time — the demo's `…-capture-ceps-load-29838195` is 2026-09-24T23:15Z), provided that instant is a firing instant of the manifest's cadence within the last day; otherwise the newest firing instant of the cadence at or before *now* (a manual Job, a laptop run). A tick that no capture served is still missing: the fallback never invents an older instant. | The gap detector (ADR-031) indexes by exact cron instants; `now()` at 23:15:25 never matches 23:15:00, so every good capture was a phantom gap and a second fetch. Rounding to the minute would misattribute a late start; the controller's tick is the intended identity the reviewer asks for. |
| P13-D2 | **The derivation identity carries the implementation.** `energy_platform.implementation_version()` = `<package version>+<sha256 over every .py of the package, first 12 hex>`, computed once per process; it replaces the bare `__version__` in `derivation_for` and in the generic `parser_ref`. A code change is a new derivation; the same code is the same derivation on a laptop and in the image (the image copies the same files). ADR-023 amendment 3. The consequence ADR-023 already accepted ("every platform release changes `derivation_id` for every target") is now true instead of hypothetical. | A parser fix that leaves the manifest alone must produce a distinguishable version (ADR-023 §1); a version string nobody bumps cannot carry that. A digest is self-enforcing; a release checklist is not. |
| P13-D3 | **The drill rebuilds every target before it compares any**, and each comparison is scoped to the target's own lineage (the rows its own attempts produced), with a fingerprint the rebuild attributes to a sibling target counted as reproduced, not missing. | Two committed targets share `ote.imbalance_settlement`/SOAP; the first target's comparison saw the second's rows before they existed in the rebuild (8 916 "missing" on an empty scratch, a pass on a warm one). Order and warmth must not decide a drill. |
| P13-D4 | **The Bronze-only rebuild guarantees values, not derivation ids.** Per (observation identity, payload) live holds within the replica bound, the rebuild must reproduce the value of live's **newest derivation** for that pair; a pair the rebuild lacks entirely is `missing` (loss), a pair whose value differs is `diverging` (the running code no longer produces live's value from that payload: an un-replayed correction or a regression — the drill fails and names it); versions under retired derivations are `historical` (counted, named, not compared — the physical backup keeps them, and the drill's first phase proves that backup). ADR-036 amendment 5 replaces §5's comparison sentence. | Old code is not in the replica; demanding its output from a current-code rebuild is a false failure on every manifest evolution (the reviewer's harmless `ignore_fields` case). Demanding the *values* keeps the loss signal and adds one the old drill lacked: live disagreeing with the code it runs. |
| P13-D5 | **Alert evaluation and delivery are part of the chart**, `alerting.enabled` (off in the tenant default; on in `local`, the demo and the all-flags render): Prometheus (image by digest, uid 65534, an `emptyDir` TSDB with 2 days of retention) loads the existing `<release>-alert-rules` ConfigMap unchanged and scrapes the exporter and a **namespaced kube-state-metrics** (`--namespaces=<release namespace>`, `--resources=cronjobs,jobs`, a Role — no ClusterRole, no CRD); Alertmanager routes every alert to the **platform receiver** — `energyctl alert-sink`, a Deployment on the platform image that records each delivery as one JSON line (`firing`/`resolved`, alert names, labels) — and to whatever `alerting.receivers`/`alerting.routes` the operator adds (SMTP, a webhook); Grafana gains the Prometheus datasource so `freshness.json` works. Egress rules: Prometheus → exporter, kube-state-metrics, Alertmanager; kube-state-metrics → the API server (`alerting.kubeStateMetrics.apiServer.cidrs`/`port`, required when on: the NetworkPolicy idiom for a tenant that knows its cluster); Alertmanager → the sink and, optionally, `alerting.egress.cidrs` for an external receiver. ADR-040. | The rules named kube-state-metrics since ADR-037 and no render ran an evaluator; a rule nobody evaluates is documentation. The receiver on the platform image keeps the proof inside the chart (no fourth image) and leaves the real channel to values. The sink lives under `energy_platform/fetch/` like the policy gate: the one package that owns sockets (ADR-027 §3). |
| P13-D6 | **The delivery drill** (`make alert-drill`, `deployment/local/drills/alert.sh`): on kind, create a Job named `<release>-restore-drill-manual-fail` whose only container exits 1; wait for the sink to log `EnergyPlatformRestoreDrillFailed` `firing`; delete the Job; wait for `resolved`. Recorded in `docs/07` §7.2. The same steps are the author's on the demo (Level 3). | The closure asks for a controlled failure producing a delivered alert and a recovery notification; the drill-failed rule fires one minute after a failed Job, so the whole exercise takes minutes and touches no data. |
| P13-D7 | **The availability boundary is written down** (ADR-028 amendment 1): the demo is a *recoverable single-primary* deployment — durable capture in two failure domains, physical and Bronze-only recovery drilled — with **no automatic failover** of the database or the control plane; the loss of the server is an outage ended by the restore procedure of `docs/07` §5 (measured only for the warm phases). A-6's "recovery has no manual step" holds for the data path (reconcile, backfill, replay, invalidation) and not for node loss on the demo. The production path (three k3s servers with embedded etcd, CNPG with replicas) is a values and Terraform change that is **not exercised**. Whether to fund and run a failover demonstration is the author's decision; until then the README and the final report say "recoverable, not highly available in the failover sense". | The reviewer is right that ADR-028's devil's-advocate paragraph accepted the outage without saying what the brief's "high availability" then means for this delivery; the final report said the opposite. Either a demonstration or a stated boundary; this phase can only do the second. |
